## Characterization

- Currently, task dispatch and attempt execution rely on ambient runtime state, conversation history, or unstructured ad-hoc arguments (Finding F-008).
- Execution interfaces across providers (Antigravity status/headless, Codex App Server JSON-RPC, local workers) lack a canonical, self-contained contract that encapsulates task goals, workspace context, input context refs, role, and capabilities without coupling to conversation transcripts (Finding F-013).
- Furthermore, provider assignments and attempts do not durably record or enforce the cryptographic `PlanDigest` of the governing `MASTER_PLAN.md` (Finding F-009). If a living plan changes while an attempt is running or pending, the system cannot detect stale plan drift, risking execution against obsolete requirements (Risk Register line 246).

## Scope

1. Introduce `TaskEnvelope` domain model in `internal/harness/model` (and dedicated envelope package `internal/harness/task`):
   - Provenance & lineage: `ID`, `TaskID`, `WorkflowRunID`, `NodeID`, `NodeRunID`, `AttemptID`, `AttemptNumber`.
   - Plan authority: `PlanDigest` (SHA-256 hex digest of governing `MASTER_PLAN.md`).
   - Task specification: `TaskClass`, `Title`, `Objective`, `Instructions`.
   - Context references: `ContextRefs` (`ID`, `URI`, `Digest`, `Role`, `Description`).
   - Workspace boundaries: `WorkspaceSpec` (`RootPath`, `RepoID`, `BaseCommit`, `WorktreeID`, `ReadOnly`).
   - Role & authority: `Role` (`RoleCoordinator` vs `RoleWorker` per I-031/I-032).
   - Constraints: `RequiredCapabilities`, `ForbiddenCapabilities`, `DeterminismClass`, `Timeout`.
   - Guidance hints: `PreferredProvider`, `PreferredModel`, `MaxTokens`, `Metadata`.
2. Provide canonical serialization, validation, and deterministic hashing:
   - `Validate() error`: strict validation of required fields, 64-hex lowercase `PlanDigest`, valid timestamps and timeouts.
   - `Digest() (string, error)`: deterministic, field-order-independent canonical SHA-256 digest of the task envelope.
   - `MatchesPlan(planDigest string) bool`: plan digest matching and drift detection.
3. Bind `PlanDigest` to `ProviderAssignment`:
   - Add `PlanDigest` field to `harnessmodel.ProviderAssignment`.
   - Append migration v16 to SQLite store (`migration_v16_plan_digest.go`) adding `plan_digest TEXT NOT NULL DEFAULT ''` and index on `provider_assignments`.
   - Update SQLite store `CreateProviderAssignment`, `GetProviderAssignment`, and list queries to persist and scan `plan_digest`.
4. Integration and conversion helpers:
   - `ToSelectorRequest(env TaskEnvelope) selector.Request`: bridge from `TaskEnvelope` to T-012 explainable shadow selector.
   - `ComputePlanDigest(content []byte) string`: canonical plan digest computation.
   - Stale plan detection sentinel: prove that attempts with mismatched plan digests are detected and rejected.

## Invariants Maintained

- **I-001 Plan authority:** `MASTER_PLAN.md` is semantic truth; generated projections are rebuildable and digest-bound.
- **I-002 Explainable assignment:** provider-backed attempts trace task, attempt, worker, account, model, session, and plan revision.
- **I-013 Migration immutability:** released migrations v1..v15 are untouched; migration v16 is strictly append-only.
- **I-030 Plan revision binding:** successful task completion and provider routing bind to verified SHA-256 plan digest.
- **I-031 / I-032 Typed worker authority:** `TaskEnvelope.Role` preserves coordinator vs worker role separation.

## Protected Surfaces

- Released SQLite migrations v1..v15 are immutable.
- Existing scheduler, lease runtime, effect runtime, and retry runtime continue passing without regression.
- No credential or network transmission.
- No write execution leases enabled prematurely (T-014 remains read-only).

## Rollback Strategy
