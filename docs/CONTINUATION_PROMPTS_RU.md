# Универсальные Промпты для Продолжения Задач (Continuation Prompts)

Настоящее руководство содержит набор эталонных универсальных промптов для продолжения работы агентов над проектом. Они подходят для любой платформы (**Antigravity**, **DeepSeek Harness**, **Claude Code**, **Cursor**, **Windsurf**, **Aider**), как для текущего чата, так и после сжатия/очистки контекста или при старте новой сессии.

---

## 1. Минималистичный промпт (Для слэш-команд и быстрого продолжения)

Рекомендуется для отправки в текущем чате или в связке со слэш-командой `/goal`:

```markdown
/goal Продолжай автономный цикл разработки по MASTER_PLAN.md. Синхронизируй ветку main, прочитай последний Context Compression Checkpoint, выбери следующую готовую задачу (READY/NEXT), оформи Pre-flight, реализуй с верификацией тестами и зафиксируй результат. Не останавливайся на промежуточных шагах.
```

---

## 2. Универсальный рабочий промпт (Стандарт для новых сессий)

Рекомендуется использовать при открытии нового диалога, передаче задачи другому агенту или после сжатия контекста:

```markdown
Продолжай выполнение проекта в соответствии с инженерным регламентом Living Plan.

Инструкции по шагам:
1. СИНХРОНИЗАЦИЯ И АНАЛИЗ:
   - Проверь git-статус и ветку (`git status`, актуальность с `origin/main`).
   - Прочитай файл `MASTER_PLAN.md` и найди последний блок `### Context Compression Checkpoint`.
   - Определи текущую активную или следующую разблокированную задачу со статусом `READY` / `NEXT`.

2. ПОДГОТОВКА (PRE-FLIGHT):
   - Зафиксируй выбранную задачу (переведи в статус `IN_PROGRESS`).
   - Сформулируй pre-flight контракт (root-cause, инварианты, границы изменений, защищаемые поверхности, план верификации и отката).

3. РЕАЛИЗАЦИЯ И ВЕРИФИКАЦИЯ:
   - Реализуй минимальное архитектурно верное решение без временных костылей.
   - Проведи верификацию по лестнице: компиляция/линтер -> целевые юнит-тесты -> тесты на гонки (-race) -> интеграционные тесты -> бенчмарки/мутации.
   - Не ослабляй проверки и не игнорируй упавшие тесты.

4. ФИКСАЦИЯ И СВЕРКА:
   - Обнови `MASTER_PLAN.md` (отметь задачу `DONE`, закрой связанные `Findings`, актуализируй DAG и следующий `NEXT TASK`).
   - Обнови `Context Compression Checkpoint` со всеми ключевыми полями.
   - Закоммить изменения атомарно и запушь в `origin/main` (без force).
   - Если используется `agctl`, выполни `agctl state complete` с фиксацией доказательств верификации.

Принцип автономности: не запрашивай подтверждений на очевидные шаги, владей конечным результатом задачи от начала до полной квалификации. Начинай.
```

## 3. Строгий контрактный промпт (Для глубокого автономного цикла / Deep Loop)

Используется для исключения «ленивого поведения агента» (когда агент только строит планы, но не пишет код, либо бросает задачу на полпути):

```markdown
### ДИРЕКТИВА: ПРОДОЛЖЕНИЕ АВТОНОМНОГО ЦИКЛА РАЗРАБОТКИ

Ты являешься ведущим инженером, владеющим полным циклом поставки (End-to-End Delivery). Тебе делегирован конечный результат, а не единичный промежуточный шаг.

#### Обязательные правила исполнения:
1. **Источник истины**: Единственным роадмапом и источником требований является `MASTER_PLAN.md`. Никаких параллельных планов или недокументированных допущений.
2. **Атомарность**: Выбирай строго одну задачу с наивысшим приоритетом из очереди `READY / NEXT`.
3. **Pre-flight First**: Перед правкой продуктового кода зафиксируй предполётный маркер (в `.engineering/preflight/` или в плане) с описанием:
   - Root Cause & Characterization
   - Invariants Maintained
   - Protected Surfaces (неприкосновенные миграции/модули)
   - Verification Ladder & Edge Space
4. **Лестница проверок (Cheap to Expensive)**:
   - Форматирование и статический анализ (`go vet`, линтеры).
   - Целевые юнит-тесты и edge-space сценарии.
   - Concurrency & Race detection (`-race`).
   - Тесты на мутации (уничтожение дефектов) и бенчмарки производительности.
5. **Завершение и сжатие контекста**:
   - Обнови реестр находок (`Findings`) и зависимости DAG.
   - Сформируй `Context Compression Checkpoint` с 15 обязательными полями (`CURRENT HEAD`, `CRITICAL INVARIANTS`, `COMPLETED`, `RESOLVED FINDINGS`, `NEXT TASK`, `VERIFICATION COMMANDS` и др.).
   - Закоммить, сделай push в `origin/main`, подтверди через `agctl state complete`.

НЕ останавливайся после составления плана. НЕ спрашивай разрешения на запуск тестов или коммит. Начинай с шага 1 (чтение чекпоинта и выбор задачи).
```

## 4. Промпт для целевой атомарной задачи `T-XXX`

Используется, когда нужно явно направить агента на конкретную задачу из реестра:

```markdown
Возьми в работу задачу [T-XXX: Название задачи] из MASTER_PLAN.md:
1. Переведи статус в IN_PROGRESS и создай pre-flight контракт.
2. Реализуй корневое исправление с соблюдением системных инвариантов.
3. Прогони тесты, проверь отсутствие регрессий и race conditions.
4. Актуализируй MASTER_PLAN.md, обнови чекпоинт, закомить и запушь в main.
```

---

## 5. Промпт восстановления после сбоя или рассинхронизации (Recovery Prompt)

Используется, если предыдущий агент допустил ошибку, сломал тесты или запутался в контексте:

```markdown
ВНИМАНИЕ: Произошел сбой или рассинхронизация контекста. Выполни восстановление:
1. `git status` и `git diff`: оцени текущее состояние рабочей директории.
2. Запусти базовые тесты проекта, чтобы выявить точное место поломки.
3. Проверь последний коммит в `git log -n 3` и последний чекпоинт в `MASTER_PLAN.md`.
4. Сформулируй гипотезу сбоя, устрани причину ошибки, добейся прохождения тестов.
5. Зафиксируй исправленное состояние и доведи задачу до штатного завершения.
```

---

## 6. Ключевые особенности работы с платформами

| Платформа | Рекомендация по передаче контекста |
|---|---|
| **Antigravity** | Работает встроенный хук `agctl state complete`. Используйте `/agctl-loop` или `/goal`. |
| **DeepSeek Harness** | Запуск через `agctl-dsh` в `pwsh` с sidecar бинарником `agctl.exe`. |
| **Claude Code** | Используйте Вариант 2 или 3. Убедитесь, что агент выполняет запуск команд без остановки на пояснения. |
| **Cursor / Windsurf** | Вставьте Вариант 3 в Composer/Agent режим (Command/Ctrl + I) с селектором кодовой базы (`@codebase`). |
