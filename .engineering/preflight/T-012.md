## Characterization

- T-008 provides deterministic session/context brokering with reuse hysteresis and no-inference sentinels.
- T-009 provides normalized native-unit capacity and conservative effective headroom without summing unlike metrics.
- T-010 provides empirical p80 demand estimation scoped by provider and metric with classified usage history.
- T-011 provides atomic provider reservations committing against complete active claims.
- The system currently lacks an integrated, explainable provider selector that combines these subsystems into a deterministic routing recommendation in shadow mode.
- Store contracts already support read-only views of accounts, models, capacity snapshots, sessions, circuits, and reservations; no schema migration is required.

## Scope

1. Implement `internal/harness/provider/selector` as a pure, deterministic multi-candidate evaluation engine.
2. Implement hard filters for candidate elimination:
   - Account state (ACTIVE, or DRAINING only if reusable session exists; DISABLED excluded).
   - Provider health (not UNAVAILABLE or EXHAUSTED).
   - Model presence, enablement (`Enabled == true`), and capability satisfaction.
   - Context limits (context limit >= required context).
   - Circuit breaker state (not OPEN).
   - Session broker viability (excluding UNAVAILABLE actions).
   - Quota headroom feasibility (demand must not exceed quantified headroom).
3. Implement soft multi-dimensional scoring in `[0, 1]` with explainable weighted criteria:
   - Headroom score (normalized effective remaining fraction).
   - Reset horizon score (favors imminent reset windows with ample capacity).
   - Session reuse score (bonus for REUSE to minimize session cold-start and context thrashing).
   - Reliability score (HEALTHY > DEGRADED > UNKNOWN; circuit half-open penalty).
   - Switch penalty (hysteresis against switching away from preferred session/provider).
   - Uncertainty penalty (penalizes stale observations or low-confidence capacity/history).
4. Implement strict deterministic tie-breaking:
   - Identical scores break ties lexically and deterministically across candidate properties.
   - 100-trial shuffled-order invariance tests.
5. Provide durable, structured rationale with:
   - Selected candidate attribution.
   - Score breakdown per criterion.
   - Elimination reasons for all rejected candidates.
6. Provide a `StoreSource` or query adaptor to read candidate state atomically within one `Store.View`.
7. Benchmarks and regression tests matching the performance baseline.

## Protected surfaces

- No released SQLite migration changes.
- No write execution or lease modification (pure shadow selector).
- No cross-metric quota arithmetic or guessing denominators.
- No credential or network transmission.
- No mutable global state.
