## Characterization

- No provider selector package exists yet; routing policy is not centralized.
- T-009 already produces conservative normalized capacity with explicit evidence state, reset horizon, freshness/confidence and native-unit windows.
- T-010 already produces provider/model/native-metric p80 reservation demand; the selector must consume it without converting metrics or inventing missing demand.
- T-008 already owns authoritative session/context decisions and hysteresis; the selector must consume its decision/reason rather than duplicate session policy.
- T-011 already owns the atomic feasibility + reservation transaction. Shadow selection must not reserve or mutate assignment state; it may only rank candidates using a conservative feasibility projection, with T-011 remaining final execution authority.
- ProviderCircuitState already exists as account/model-scoped protection state and should be a hard availability input when authoritative OPEN state is known.
- Existing ProviderAssignment history can provide switch/stickiness context, but selector explanation needs a durable, immutable shadow-decision record rather than mutating assignment history.

## Scope

Implement a provider-neutral shadow selector that:

1. builds candidates from durable account/model/capacity/session/circuit inputs;
2. applies explicit hard filters for account state, provider health/evidence, enabled model, required capabilities, risk allowance, context/session availability and native-unit demand feasibility;
3. scores surviving candidates with normalized, bounded components for quota headroom/reset horizon, session reuse, reliability/circuit state, switch cost and evidence uncertainty;
4. uses deterministic tie-breaking independent of input ordering;
5. returns stable machine-readable exclusion and scoring reasons;
6. persists an immutable shadow decision/rationale without creating ProviderAssignment or ProviderReservation rows;
7. leaves atomic reservation to T-011 when later routing modes become executable.

## Protected surfaces

- No changes to released migrations v1..v15; append-only migration only if durable shadow-decision persistence requires it.
- No provider credentials, network listeners or provider execution behavior.
- No change to T-011 reservation correctness, lease fencing, worker authority or main-write policy.
- No inferred Codex thread->model/session affinity, quota bucket->model mapping, demand classification or unit conversion.
- No automatic execution/routing mode enablement; T-012 remains SHADOW only.

## Edge-space / adversarial matrix

`account state × provider health/evidence × model enabled/capabilities × circuit account/model state × demand available/native metric × quota windows/model applicability × reset/freshness × session action/headroom × risk allowed × prior assignment/switch identity × input order × equal-score ties`.

Important boundaries: exact capacity-vs-demand equality; stale/unknown/partial evidence; reset-now; OPEN vs HALF_OPEN circuit; DRAINING account; session REUSE vs NEW vs CHECKPOINT_AND_NEW vs UNAVAILABLE; missing demand; OPAQUE demand; model-specific vs account-wide windows; zero/one score components; deterministic lexical tie.
