## Characterization

- T-014 established automatic read-only provider routing (`TaskEnvelope.Workspace.ReadOnly == true`).
- T-015 established provider fault classification, retry/failover decisions, and circuit breaker state management.
- T-016 established safe provider handoff with fail-closed in-doubt effect reconciliation.
- Multi-provider execution requires allowing workers to produce code edits, documentation, and file generation without writing directly to the production branch or un-isolated primary workspace.
- Writing directly to primary workspace files from concurrent or untrusted provider executions risks un-fenced mutations, merge races, and workspace corruption.
- Invariant I-006 ("Execution fencing: task execution is bound by lease and attempt"), Invariant I-032 ("Typed worker authority"), and Invariant I-030 ("Plan revision binding") require that all write routing occurs strictly in isolated scratch/worktree environments (`WorkspaceSpec.Isolated == true`) before fenced verification and commit coordination (T-018/T-019).

## Scope

1. Update `internal/harness/model/task_envelope.go`:
   - Extend `WorkspaceSpec` with `Isolated bool`, `IsolationRoot string`, `WriteLeaseID string`.
   - Update `WorkspaceSpec.Validate()` to enforce that non-read-only workspaces require `Isolated == true` and non-empty `IsolationRoot` or `WorktreeID`.
2. Enhance `internal/harness/provider/router`:
   - `ErrIsolatedWriteRequired` indicating non-read-only envelope without write isolation.
   - `IsolatedWriteExecutorFunc`:
     - Callback signature: `func(ctx context.Context, env harnessmodel.TaskEnvelope, assignment harnessmodel.ProviderAssignment) (output IsolatedWriteOutput, err error)`.
     - `IsolatedWriteOutput`: `ModifiedFiles []string`, `DiffSummary string`, `Output string`, `TokensUsed int64`.
   - `Router.RouteIsolatedWrite(ctx, env, currentPlan) (RouteResult, error)`:
     - Validates envelope and plan digest freshness (`task.CheckPlanDrift`).
     - Enforces write isolation constraints (`env.Workspace.Isolated == true && env.Workspace.IsolationRoot != ""`).
     - Evaluates provider selection requiring write capabilities (`file_edit`, `tools`).
     - Commits `ProviderAssignment` (state `ACTIVE`, revision 1, `PlanDigest` bound) and `ProviderReservation` in SQLite transactional store.
   - `Router.ExecuteIsolatedWrite(ctx, route, executor) (ExecutionResult, error)`:
     - Safely dispatches write execution callback.
     - Settles ledger atomically: on success -> `RELEASED` reservation, `COMPLETED` assignment, `circuit.RecordSuccess`; on error -> classifies fault, updates circuit, computes retry decision, settles `RELEASED` reservation and `FAILED` assignment.
3. Tests, benchmarks, and mutation tests:
   - Matrix tests for isolated write routing: valid isolated write, unisolated write rejection (`ErrIsolatedWriteRequired`), plan drift rejection (`ErrStalePlan`), capability matching (`file_edit`), ledger settlement on success and failure.
   - 64-way concurrent isolated write routing and execution sentinel under `go test -race`.
   - Mutation tests killing defects that bypass write isolation, omit `PlanDigest` binding, or leak quota reservations.
   - Permanent CI smoke benchmark: `BenchmarkIsolatedWriteRouterDispatch100Operations`.

## Invariants Maintained

- **I-001 Plan authority:** write routing is strictly bound to verified `PlanDigest` of `MASTER_PLAN.md`.
- **I-002 Explainable assignment:** write routing records durable rationale and candidate elimination reasons.
- **I-006 Execution fencing:** write execution is isolated from primary production workspace.
- **I-010 / I-011 Quota integrity:** atomic quota reservations commit and release symmetrically.
- **I-023 Durable routing history:** at most one `ACTIVE` assignment per attempt; assignments are never mutated or deleted.
- **I-024 Reservation lifecycle fencing:** reservations start `ACTIVE` revision 1 and terminalize via atomic CAS.
- **I-030 Plan revision binding:** plan drift during write routing fails closed (`ErrStalePlan`).
