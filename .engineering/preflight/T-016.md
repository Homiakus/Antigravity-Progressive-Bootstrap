## Characterization

- T-013 established conversation-independent `TaskEnvelope` and cryptographic `PlanDigest` binding.
- T-014 established automatic read-only routing and ledger settlement.
- T-015 established provider failure classification, deterministic retry decisions (`ActionFailover`, `ActionTripCircuitAndFailover`), and monotonic SQLite circuit breaker management.
- In multi-provider execution, when a provider fails or encounters a failover condition (e.g. rate limits, transient network overload, model downtime), the task attempt may have dispatched external side effects (RPCs, tool calls, file writes, API mutations).
- If provider failover occurs blindly without checking for uncertain in-flight effects (`DISPATCHED` or `IN_DOUBT`), the replacement provider could duplicate non-idempotent side effects, violating invariant I-007 ("Fail closed on uncertain effects: unsafe interruption reuses effect intents + IN_DOUBT; no blind replay").
- Invariant I-023 ("Durable routing history: provider handoff supersedes/terminalizes then appends; historical decisions are never rewritten; at most one ACTIVE assignment per Attempt") mandates that the prior assignment transitions to `SUPERSEDED`, its quota reservation is released, and a new `ACTIVE` assignment and reservation are atomically created for the replacement provider in the same transaction.

## Scope

1. Create safe provider handoff package `internal/harness/provider/handoff`:
   - `HandoffManager` / `HandoffCoordinator`:
     - Evaluates whether an attempt with an active or failed assignment can be safely handed off to a replacement provider.
     - **Effect Safety Check**:
       - Inspects all effect intents attached to the attempt via `ListEffectIntentsByAttempt`.
       - If any effect is `EffectInDoubt` or `EffectDispatched` and not `BlindRetrySafe()`:
         - Requires `EffectReconciler` to prove the effect is either `EffectReconcileAbsent` or `EffectReconcileConfirmed`.
         - If unreconciled or `EffectReconcileUnknown`: fails closed with `ErrHandoffUnsafeInDoubt`.
     - **Living Plan Verification**:
       - Validates `envelope.PlanDigest` against current plan content via `task.CheckPlanDrift`. Fails closed with `ErrStalePlan` if drift is detected.
     - **Atomic Handoff Transition**:
       - Executes inside a single `store.Update` transaction:
         - CAS transitions prior `ProviderAssignment` from `ACTIVE` to `SUPERSEDED`.
         - CAS transitions prior `ProviderReservation` from `ACTIVE` to `RELEASED`.
         - Evaluates candidate selection using `selector.Evaluate` with hard and soft criteria, excluding the failed account/model and circuit-tripped candidates.
         - Creates replacement `ProviderAssignment` in `ACTIVE` state with revision 1 bound to `PlanDigest`.
         - Creates replacement `ProviderReservation` in `ACTIVE` state with revision 1.
       - Guarantees at most one `ACTIVE` assignment per attempt at all times (matching database unique index `provider_assignments_active_attempt`).
     - **Explainable Handoff Record**:
       - Emits structured `HandoffResult` documenting prior assignment, replacement assignment, rationale, and effect reconciliation evidence.
2. Integration with `internal/harness/provider/router` and `internal/harness/provider/fault`.
3. Tests, benchmarks, and mutation tests:
   - Matrix tests for effect states (`CONFIRMED`, `FAILED`, `IN_DOUBT`, `DISPATCHED`), blind-retry safety, and reconciliation outcomes (`Absent`, `Confirmed`, `Unknown`).
   - Atomic database transition tests verifying prior assignment is `SUPERSEDED`, prior reservation is `RELEASED`, new assignment is `ACTIVE`, and unique constraint is preserved.
   - Plan drift detection test during handoff.
   - 64-way concurrency sentinel verifying no race conditions or oversubscription during parallel handoffs.
   - Mutation tests killing mutants that allow unsafe `IN_DOUBT` handoffs without reconciliation or overwrite prior assignment history.
   - CI smoke benchmark: `BenchmarkSafeProviderHandoff100Operations`.

## Invariants Maintained

- **I-001 Plan authority:** handoff is bound to verified `PlanDigest` of `MASTER_PLAN.md`.
- **I-002 Explainable assignment:** handoff records include structured reason codes and selector rationale.
- **I-006 Execution fencing:** handoff respects attempt and lease boundaries.
- **I-007 Fail closed on uncertain effects:** handoff never blindly replays uncertain non-idempotent effects; requires reconciliation.
- **I-010 / I-011 Quota integrity:** prior reservation is released and replacement reservation is committed atomically.
- **I-023 Durable routing history:** prior assignment transitions to `SUPERSEDED`; replacement assignment is appended; historical decisions are never rewritten; at most one `ACTIVE` assignment per attempt.
- **I-024 Reservation lifecycle fencing:** reservations start `ACTIVE` revision 1 and terminalize only by CAS.
- **I-030 Plan revision binding:** plan drift during handoff fails closed (`ErrStalePlan`).
- **R-005 No blind failover:** failover and handoff require failure classification and effect safety checks.
